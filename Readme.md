# PRD: Globed.ai

**Версия:** 1.0 (черновик) · **Дата:** 2026-11-01 · **Автор:** Умеджон
**Статус:** MVP-планирование · **Языки платформы:** English (en), Русский (ru), Тоҷикӣ (tj)

---

## 1. Обзор приложения и цели

**Globed.ai** (от *Global Education*) — веб-платформа с ИИ, которая помогает ученикам из Таджикистана и других стран подготовиться к поступлению в зарубежные университеты (Harvard, Stanford и др.).

**Проблема.** У школьников из Таджикистана мало доступа к персональной подготовке и понятной информации о поступлении за рубеж. Часто неясно, с чего начать, какие требования у вуза и как оценить свой уровень.

**Решение.** Ученик выбирает целевые вузы, проходит входную диагностику, после чего ИИ строит персональный план и уроки под его уровень и цели. Рядом: дашборд с прогрессом, библиотека книг, ИИ-ассистент и сообщество студентов вузов мира, делящихся реальными советами по поступлению.

**Цели продукта**
| # | Цель | Метрика успеха (предложение) |
|---|------|------------------------------|
| G1 | Помочь ученикам понять, куда и как поступать | % учеников, завершивших входную диагностику |
| G2 | Дать персональную подготовку | Среднее число пройденных уроков на ученика в неделю |
| G3 | Удержание через геймификацию | Доля учеников со стриком ≥ 7 дней |
| G4 | Покрыть расходы на ИИ подпиской | Конверсия free → Pro (цель определяется после запуска) |
| G5 | Ориентир первого года | 5000+ зарегистрированных учеников |

**Принцип монетизации:** бесплатная версия остаётся полезной; подписка Pro покрывает расходы на ИИ.

---

## 2. Целевая аудитория

**Основная (MVP):** школьники 9–11 классов из Таджикистана и других стран, которые хотят поступить в зарубежные вузы. Большинство пользователей — несовершеннолетние (учесть в безопасности, разд. 7).

**Вторичная (после MVP):** студенты, желающие перевестись в другие вузы.

**Контент-партнёры (внутри платформы):** проверенные студенты зарубежных вузов, публикующие советы.

**Внутренние роли:** супер-админ, контент-менеджер, модератор.

**Языки интерфейса и ИИ:** en, ru, tj. Язык выбирает ученик; фронтенд передаёт его бэкенду, ИИ задаёт вопросы и готовит уроки на этом языке.

## 3. Основные функции и функциональность

Все функции ниже входят в MVP. Группировка соответствует спринтам (см. разд. 8).

### F1. Аутентификация и аккаунт (Sprint 1)
- Регистрация/вход: **Google OAuth 2.0** и **email + одноразовый код (OTP)** для защиты от ботов.
- Сессии: JWT (access + refresh) или серверные сессии Django — решение на этапе реализации.
- Профиль: имя, аватар, язык, страна, класс, дата регистрации.
- Удаление аккаунта и всех связанных данных (включая историю чатов) по запросу пользователя.

**Acceptance criteria**
- Пользователь может зарегистрироваться через Google и через email с кодом.
- Код действует ограниченное время (напр. 10 мин), лимит попыток и запросов нового кода.
- Пользователь может сменить аватар и язык; язык сохраняется между сессиями.
- Кнопка «Удалить аккаунт» запускает необратимое удаление после подтверждения.

**Technical Considerations:** ограничение частоты запросов (rate limiting) на отправку кодов; email-провайдер для отправки OTP (определить); защита от перебора кода.

### F2. Мультиязычность (Sprint 1)
- UI на en/ru/tj через i18n (Next.js).
- Выбранный язык передаётся в каждый запрос к бэкенду (заголовок или поле профиля).
- ИИ получает язык как параметр и отвечает/генерирует на нём.

**Acceptance criteria**
- Все статические тексты интерфейса переведены на 3 языка; нет «сырых» ключей в UI.
- Входные вопросы и уроки генерируются на языке пользователя.
- Для tj предусмотрена проверка качества ключевых шаблонов промптов (ИИ на таджикском слабее, чем на en/ru).

### F3. Выбор университетов (Sprint 2)
- База вузов хранится **в собственной БД** и наполняется вручную контент-менеджерами (решение владельца).
- Ученик выбирает один или несколько целевых вузов, может изменить выбор позже.

**Acceptance criteria**
- Поиск и фильтрация вузов по названию/стране.
- Карточка вуза: название, страна, описание, требования к поступлению, ссылки.
- Ученик может добавить/удалить вуз из целей; минимум 1 вуз для продолжения.

### F4. Входная диагностика (Sprint 2)
- ИИ генерирует **10–15 вопросов** для определения уровня ученика с учётом выбранных вузов и языка.
- Ответы сохраняются; ИИ определяет стартовый уровень по предметам/навыкам.

**Acceptance criteria**
- После выбора вузов ученик получает 10–15 вопросов на своём языке.
- После завершения ученик перенаправляется на дашборд.
- Результаты записываются в `SubjectLevel`; диагностику можно пройти повторно.

**Algorithm (псевдокод)**
```
input: student_id, target_universities[], language
1. context = build_context(target_universities.requirements, student.grade)
2. questions = ai.generate_questions(count=10..15, language, context)
3. validate(questions): schema ok, count in range, language matches
4. store questions as AssessmentSession
5. on submit: ai.evaluate(answers) -> levels per subject
6. save SubjectLevel[], mark onboarding_completed = true
```
**Technical Considerations:** строгий JSON-формат ответа ИИ с валидацией; повтор при невалидном ответе; фоновые задачи (Celery).

### F5. Персональные уроки от ИИ (Sprint 3)
- ИИ генерирует уроки под уровень ученика и требования целевых вузов.
- Подход различается у разных учеников в зависимости от `SubjectLevel`.
- Урок сохраняется, чтобы не генерировать повторно.

**Acceptance criteria**
- Ученик видит рекомендованную последовательность уроков на дашборде.
- Урок открывается на языке ученика; завершение урока фиксируется и даёт очки (XP).
- Уровень обновляется по результатам заданий.
- Free: ограниченное число ИИ-уроков в день (лимит TBD); Pro: без лимита.

**Technical Considerations:** генерация в фоне (Celery + Redis); кэширование; контроль стоимости (лимиты токенов на запрос); пользователь видит статус «урок готовится».

### F6. Дашборд ученика (Sprint 3)
- Показатели: уровень по предметам, прогресс, стрик, XP, пройденные уроки.
- Рекомендации ИИ: что изучать дальше.
- Быстрые входы: библиотека, ИИ-ассистент, сообщество.

**Acceptance criteria**
- Дашборд загружается с актуальными данными ученика.
- Блок рекомендаций обновляется по результатам уроков.

### F7. Геймификация и стрики (Sprint 3)
- Стрик (серия дней активности) в стиле Duolingo, XP, уровни, прогресс-бары.
- День засчитывается при выполнении минимального действия (напр. завершён урок) — правило уточнить.

**Acceptance criteria**
- Стрик увеличивается один раз за календарный день активности; сбрасывается при пропуске.
- Часовой пояс пользователя учитывается при определении «дня».
- Очки и стрик отображаются на дашборде и в профиле.

### F8. Библиотека книг (Sprint 4)
- Книги добавляются через админку контент-менеджерами; ученики читают их на платформе.

**Acceptance criteria**
- Контент-менеджер может создать/изменить/скрыть книгу (название, автор, описание, файл, язык, категория).
- Ученик может искать, открывать и читать книгу; запоминается место чтения (опционально).

**Technical Considerations:** хранение файлов (объектное хранилище); вопрос авторских прав на загружаемые книги — ответственность контент-менеджера; рекомендуется загружать только материалы со свободной лицензией или с разрешением.

### F9. ИИ-ассистент (Sprint 4)
- Чат с ИИ-ассистентом по вопросам подготовки и поступления; история сохраняется.
- Ответы на языке ученика; контекст — профиль, цели и уровень.

**Acceptance criteria**
- Ученик может создать диалог и продолжить предыдущий.
- Free: лимит сообщений в день (TBD); Pro: без лимита.
- Ученик может удалить историю чата.

### F10. Сообщество: советы студентов вузов (Sprint 5)
- Страница, где **проверенные студенты** вузов мира публикуют советы по поступлению.
- **Модерация:** первые 3–5 постов нового автора проверяются строго; затем режим смягчается.
- Ученики читают советы, фильтруют по вузу/стране/теме.

**Acceptance criteria**
- Только пользователи со статусом `verified_student` могут публиковать.
- Пост нового автора попадает в очередь модератора и публикуется только после одобрения.
- После N одобренных постов (3–5, настраиваемо) автор переходит в режим «доверенный»: публикация сразу, с возможностью последующей жалобы.
- Любой пользователь может пожаловаться на пост; модератор видит очередь жалоб.

**Технические детали проверки студента (рекомендация):** подтверждение через университетскую почту; альтернатива — ручная проверка документа модератором.

### F11. Подписки (Sprint 5)
- Планы: Free и Pro; Pro на **фиксированный срок** (напр. 1/3/12 месяцев) с **единоразовой оплатой**, **без автопродления**.
- Скидка за долгий срок.

**Acceptance criteria**
- Пользователь видит планы, цены и срок; после оплаты Pro активируется до даты окончания.
- По окончании срока доступ автоматически возвращается к Free.
- Админ может менять цены и сроки планов.

**Технические ограничения платежей (результат исследования):** Stripe напрямую недоступен для бизнеса в Таджикистане; Alif — локальный кошелёк для рынка Таджикистана, но по данным интеграционных справок он не поддерживает рекуррентные платежи. Поэтому выбрана модель фиксированных периодов. Условия провайдеров и ограничения для физлица нужно проверить напрямую. Для учеников из других стран позже можно добавить международную оплату через зарубежное юрлицо.

### F12. Админка и роли (Sprint 1–5, по мере появления сущностей)
| Роль | Права |
|------|-------|
| Super Admin | Всё: пользователи, роли, планы, настройки, данные |
| Content Manager | CRUD вузов и книг |
| Moderator | Проверка и модерация постов сообщества, жалобы |

**Acceptance criteria:** доступ к разделам админки строго по роли; действия модерации логируются.

| Слой | Выбор | Обоснование |
|------|-------|-------------|
| Frontend | **Next.js + TypeScript + i18n** | Выбрано владельцем; SSR/SEO, мультиязычность |
| Backend | **Python + Django (+ Django REST Framework)** | Выбрано владельцем; готовая админка и роли, зрелая экосистема |
| База данных | **PostgreSQL** | Связанные данные: ученики, вузы, уроки, посты, подписки |

| Аутентификация | Google OAuth 2.0 + email OTP | Выбрано владельцем |

**Рекомендация по ИИ-слою:** вынести работу с ИИ в отдельный модуль бэкенда (единый интерфейс: `generate_questions`, `evaluate_answers`, `generate_lesson`, `chat`), чтобы менять модель без переписывания платформы и использовать разные модели для разных задач.

## 5. Концептуальная модель данных

Поля и типы концептуальные; конкретные имена уточняются при реализации.

**User**: id (uuid), email (string, unique), auth_provider (enum: google|email), role (enum: student|content_manager|moderator|super_admin), language (enum: en|ru|tj), created_at (datetime), deleted_at (datetime, nullable)

**TargetUniversity** (N:M StudentProfile–University): student_id, university_id, priority (int), added_at

**AssessmentSession**: id, student_id (FK), language (enum), questions (json), answers (json), status (enum: generated|submitted|evaluated), created_at

**SubjectLevel**: id, student_id (FK), subject (string), level (string/int), source_session_id (FK), updated_at

**Lesson**: id, student_id (FK), subject (string), title (string), content (json/text), language (enum), status (enum: generating|ready|failed), created_at

**LessonProgress**: id, lesson_id (FK), student_id (FK), status (enum: not_started|in_progress|completed), score (float, nullable), completed_at

**StreakRecord**: student_id (FK, unique), current_streak (int), longest_streak (int), last_active_date (date)

**XPEvent**: id, student_id (FK), points (int), reason (string), created_at

**Book**: id, title, author, description, language, category, file_url, is_published (bool), created_by (FK User)

**ChatSession**: id, student_id (FK), title (string), created_at
**ChatMessage**: id, session_id (FK), role (enum: user|assistant), content (text), created_at

**TipPost**: id, author_id (FK User), university_id (FK, nullable), title, body (text), language, status (enum: pending|approved|rejected|hidden), created_at, reviewed_by (FK, nullable), reviewed_at

**AuthorTrust**: author_id (FK, unique), approved_posts_count (int), is_trusted (bool)

**PostReport**: id, post_id (FK), reporter_id (FK), reason (text), status (enum: open|resolved), created_at

**Plan**: id, name, duration_months (int), price (decimal), currency (string), discount_percent (int), is_active (bool)

**Subscription**: id, user_id (FK), plan_id (FK), starts_at, ends_at, status (enum: active|expired)

**Payment**: id, user_id (FK), plan_id (FK), amount (decimal), provider (string), provider_ref (string), status (enum: pending|paid|failed), created_at

**UsageCounter**: user_id (FK), date (date), ai_messages (int), ai_lessons (int) — для лимитов Free

**Связи (кратко):** User 1—1 StudentProfile; StudentProfile N—M University через TargetUniversity; StudentProfile 1—N Lesson/ChatSession/AssessmentSession; User 1—N TipPost; User 1—N Subscription.

## 6. Принципы UI-дизайна

- **Стиль:** сочетание **Duolingo** (геймификация, дружелюбность) и **чёрно-белой** палитры (строгость, академичность).
- **Акцентный цвет:** один дополнительный цвет для состояний (правильно/неправильно, достижения, стрик) — иначе в ч/б сложно показывать обратную связь.
- **Геймификация:** стрик, XP, уровни, прогресс-бары, понятные награды.
- **Адаптивность:** mobile-first веб (основная аудитория — школьники на телефонах); мобильное приложение — после MVP.
- **Мультиязычность в дизайне:** текст tj/ru длиннее en — макеты должны выдерживать разную длину.
- **Доступность:** контрастность, читаемые шрифты, поддержка кириллицы и таджикских символов (ғ, ӣ, қ, ӯ, ҳ, ҷ).
- **Макеты:** wireframes на данный момент отсутствуют — подготовить для ключевых экранов (вход, выбор вузов, диагностика, дашборд, урок, чат, сообщество, подписка).

## 7. Соображения по безопасности

- **Несовершеннолетние:** минимизировать хранимые персональные данные; чётко описать политику конфиденциальности; удаление аккаунта и истории чатов по запросу.
- **Аутентификация:** OTP с ограничением срока/попыток; rate limiting; защита от ботов.
- **Авторизация:** доступ к админке по ролям; проверка прав на каждом эндпоинте.
- **Данные:** HTTPS везде; хэширование/шифрование чувствительных данных; регулярные бэкапы БД.
- **ИИ:** фильтрация и валидация ответов ИИ; ограничения на длину и стоимость запросов; не отправлять в ИИ лишних персональных данных.
- **Сообщество:** модерация, жалобы, проверка статуса студента, запрет рекламы и спама.
- **Платежи:** не хранить данные карт у себя; использовать платёжного провайдера.
- **Лимиты и злоупотребления:** лимиты на ИИ-запросы для Free; защита от массовой регистрации.

## 9. Потенциальные проблемы и способы их решения

| Проблема | Решение |
|----------|---------|
| Качество ИИ на таджикском ниже, чем на en/ru | Тестирование на реальных примерах; шаблоны промптов с проверкой; ручная вычитка ключевых текстов; возможность смены модели |
| Высокие расходы на ИИ | Лимиты для Free; кэширование уроков; ограничения токенов; тарифы Pro |
| Достоверность информации о вузах | Ручной ввод контент-менеджерами; дата последнего обновления на карточке; регулярная проверка |
| Ошибочные/вредные советы в сообществе | Модерация, верификация студентов, жалобы |
| Оплата: Stripe недоступен, у Alif нет рекуррентных платежей, ограничения для физлица | Фиксированные периоды без автопродления; проверка условий провайдеров; регистрация юрлица позже |
